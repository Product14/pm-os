# A live rooftop cannot test its own Vini agent without the test landing in its reports and CRM

**Author:** Sales Inbound PM · **Date:** 2026-10-22 · **Status:** Draft v1 · **Ticket:** none (PM idea) · **Area:** platform
**Flywheel stage:** lead and appointment (sales), service drive appointment (service)

## Decision
Build one guided test mode for every live rooftop, on Sales and Service, running on the rooftop's own live agent and kept out of its numbers. [PM] [E1]
The judge said defer because demand is unmeasured; the PM overrode it because live rooftops already test today and those tests already land in their reports and CRM. [PM] [E63] [E56]

## TL;DR
Today a GM or service manager who wants to hear their live agent places a real call that counts like a customer call. We will give them the guided test prospects get, on the exact agent their customers reach, with a report afterwards and no trace in their reports. It removes CSM time per agent change and days a wrong hours or policy answer stays live; neither is measured yet.

## Problem
A service manager changes Saturday hours in Settings and wants to hear the agent say them before customers call. [ASSUMPTION: illustrative; no dealer has been quoted yet]
They click Talk to agent, fill in a short form, and the console places a real call on the live agent. [E3]
That call counts in the rooftop's conversation reports like a customer conversation, and a sales outbound test also creates a real lead in the CRM. [E63] [E56]
They get no report of what the agent captured and no list of past tests. [E18]
Prospects get exactly that from the guided demo, but it is shown only before go-live and blocked for live stores. [E4] [E5] [E18]
Opened as built, it would break the live agent: real browser calls would fail, every customer would be offered lease and payment estimates, and test edits would change the live hours and policies. [E6] [E7] [E8] [E15]

**Goal:** a live rooftop hears what its customers hear, sees what the agent captured, and fixes anything wrong in Settings, without the test touching its live setup, its reports or its store line. [PM]

## Evidence
- The only ask so far is the PM's: "Get the agent demo flow plugged into agents which are already live." [E1]
- The receptionist test already runs on a live rooftop's real agent and marks the call as a test, so the approach works. [E9]
- How many rooftops test today is unknown: the customer-conversation and ticket searches failed, so the count is missing, not zero. [E30] [E50]

## Recommendation
1. On Sales or Service > Settings > Agents, Talk to agent opens the guided test, pointed at the rooftop's own live agent. [E1] [PM]
2. The tester picks a browser call to the inbound agent, or has the outbound agent call their phone. [E23]
3. The agent behaves exactly as live: same script, policies, hours, inventory and finance provider. It never transfers, so the store's line never rings, and any appointment it books is marked as a test. [E21]
4. The agent's details are read-only, each with an "Edit in Settings" link; nothing in the test changes the live agent. [E21] [E15]
5. After the call the tester gets the same structured report a prospect gets, and finds every past test in the test history. [E18] [E21]
6. The call is marked as a test so it stays out of the rooftop's reports and analytics. [E9] [E21]
7. The internal demo list the Spyne sales team works from flags rooftops already live, so nobody chases a customer as a prospect. [E21]
8. It sits behind a switch: Spyne owners first on production, then every user; with it off, today's form stays. [E21]

Per rooftop, set not coded: which lanes show (only agents it has live) and the tester's phone number. [E23] [PM]
Not in v1: text-message tests, and rebuilding any part of the guided test that already works. [E24] [PM]

## Risks and dependencies
- If any path misses the live safeguard, the real agent is treated as a demo and real calls break. [E6] [E7] [E8]
- Leaks the test mark does not close: test bookings show in the overview appointments count, callback requests create real staff tasks, and a CRM lead is created under the tester's phone. Fixing them touches tools other teams own. [E12] [E13] [E14]
- The agent may send real texts during a test and reminders may fire on test bookings. [ASSUMPTION: texts and reminders are not gated for tests]
- A test service booking may write into the dealer's DMS scheduler; a UAT check on a rooftop with a working DMS connection gates rollout. [ASSUMPTION: no DMS write; Q70]
- Rooftops that tried the prospect demo before go-live may already have their real agent marked as a demo and need a check first. [ASSUMPTION: some live rooftops carry an old demo mark]
- Outbound tests ring from a shared caller ID, and demo cleanup at sales go-live could remove test leads on a rooftop already live on service. [E23] [E17]
- Demand is unmeasured; this ships on a PM call. [E30] [PM]
