## Code facts found while resolving (local clone, read-only)

These change three answers, so they are stated before the table.
1. **Outside its window, STL skips the first text; it does not hold it.** The execution gate returns `skipCurrentWorkflow` with a `stl-outside-*` reason and schedules the next step (`conversational-ai-backend:src/sequence-workflows/services/sequence-task-execution-orchestrator.service.ts:1922`, `:1946`). With the nudge off and the source excluded, a lead forwarded after the window gets no text at all. So "leads after 9 pm get the first text at window open" is not what the code does. v3 states it honestly: step 0 gives a same-evening text to leads forwarded between BDC close and the window's end; later leads are called by the BDC as today. If the production test shows a held text instead, the handoff marks those leads "text due at <time>" and the BDC holds its call until then (A5).
2. **Team silent hours do not stop an STL text.** Central silent hours skip calls and plain follow-ups, but let STL and STL follow-up SMS through (`...sequence-task-execution-orchestrator.service.ts:1487`). The only time guard is the entry's mode. `SILENT_HOURS` mode allows STL *during* silent hours, default 9 pm to 8 am (`conversational-ai-backend:src/speed-to-lead/services/speed-to-lead-console-call.service.ts:221`), the opposite of the quiet-hours rule. The window must be `CUSTOM_TIME` or `WORKING_HOURS`. It is evaluated in the team's timezone, which falls back to UTC when unset (`:216`).
3. **A source entry is an independent second gate.** `resolveStlGate` and the creation allowlist resolve a type entry (blank type normalises to the key "empty", then falls back to DEFAULT) and, where one exists, a source entry; both must pass, mode and window included (`:131`, `:396`, `:446`, `:470`, `:560`). This is the answer to backend-engineer-r2-1 below.
